本模块围绕 `Relation` 结构体组织，按职责拆分为多个文件：
- `relation.go`：定义 `Relation` 核心结构（持有 `db_interface.DataBase`、`user.User`、`OnFriendshipListenerSdk`、`conversationEventQueue`、`relationSyncMutex`），并通过 `initSyncer()` 注册两个 `syncer.Syncer`——`friendSyncer`（基于 `syncer.New2` 的带分页全量同步器）和 `blackSyncer`（基础 `New` 同步器），分别负责好友与黑名单的本地持久化与回调。
- `api.go`：面向上层 SDK 的业务 API（`GetFriendList`、`AddFriend`、`CheckFriend`、`AddBlack` 等），统一通过 `datafetcher.DataFetcher` 做“本地缓存 → 数据库 → 服务端”三级填充，并在写操作后以 `relationSyncMutex` 串行调用 `IncrSyncFriends` / `SyncAllBlackList` 保证一致性。
- `server_api.go`：纯 HTTP 封装层，所有对 `pkg/api` 的调用集中在此，仅负责组装请求并返回协议对象，不掺杂业务逻辑。
- `conversion.go`：提供 `ServerFriendToLocalFriend`、`ServerBlackToLocalBlack`、`ServerFriendRequestToLocalFriendRequest` 三个单向转换函数，作为网络模型到本地模型的唯一映射点。
- `sync.go`：黑名单全量同步入口，对比服务端与本地列表后交由 `blackSyncer.Sync` 完成 diff。
- `incremental_sync.go`：基于 `syncer.VersionSynchronizer` 的好友增量同步，先拉取 `GetFullFriendUserIDs` 校验 ID 顺序变化，再按 `VersionID/Version` 拉取增量并委托给 `friendSyncer.Sync`；同时暴露加锁版 `IncrSyncFriendsWithLock`。
- `notification.go`：订阅服务端推送的 `sdkws.MsgData`，按 `ContentType` 分发到各 Tips 类型，对涉及当前登录用户的关系变更直接触发增量/全量同步，并对新增/修改事件经 `common.DispatchUpdateConversation` / `DispatchUpdateMessage` 广播给会话与消息层。
依赖方向：本模块依赖 `pkg/db`、`pkg/syncer`、`pkg/datafetcher`、`pkg/api`、`internal/user` 与 `open_im_sdk_callback`，被上层 `open_im_sdk/` 通过 `SetDataBase` / `SetLoginUserID` / `SetListener` 注入依赖，自身不反向依赖 open_im_sdk。
