模块按职责拆分为三个文件：
- `callback_writer.go` 定义 `CallbackWriter` 接口及两个实现：`EventData`（通过 `js.Value.Invoke` 直接调用 JS 函数）和 `PromiseHandler`（基于 `syscall/js` 的 Promise resolve/reject），二者均遵循链式 `SetEvent/SetData/SetErrCode/SetOperationID/SetErrMsg` + `SendMessage()` 的构建模式。
- `listener.go` 集中实现所有业务域回调类型（`ConnCallback`、`ConversationCallback`、`AdvancedMsgCallback`、`FriendCallback`、`GroupCallback`、`UserCallback`、`CustomBusinessCallback`、`SignalingCallback`、`UploadFileCallback`、`SendMessageCallback` 等），每个类型嵌入一个 `CallbackWriter`，在各自的 `OnXxx` 方法中用 `utils.GetSelfFuncName()` 作为 event 名、`SetData/SetErrCode/SetErrMsg` 填充 payload 并 `SendMessage()`；其中 `BaseCallback` 组合 `PromiseHandler` 用于返回 Promise 的 API，而多数事件型回调使用 `NewEventData(callback)` 构造的即时回调。
- `caller.go` 提供 `Caller` 反射调度器 `ReflectCall`，从 JS 侧传入的 `[]js.Value` 参数经 reflect 类型匹配转换为 Go 函数签名所需值，支持 `AsyncCallWithCallback`/`AsyncCallWithOutCallback`/`SyncCall` 三种调用形态，并通过统一的 `ErrHandle` 把 panic 转为错误码回传。
依赖方向：本模块仅向上依赖 `open_im_sdk_callback`（被实现的回调接口）、`pkg/utils`（JSON 序列化与函数名提取）、`wasm/exec`（ArrayBuffer 提取），不反向依赖任何业务域包，是纯桥接层。
