本模块以 `Conversation` 结构体为聚合根，通过组合注入依赖完成跨子域协作：
- 依赖注入：构造器 `NewConversation` 注入 `interaction.LongConnMgr`（WebSocket）、`db_interface.DataBase`、`relation.Relation`、`group.Group`、`user.User`、`third/file.File`，并通过 `SetDataBase/SetLoginUserID/SetPlatform/SetDataDir` 等 setter 补齐运行时参数。
- 分层边界：对外 API 集中在 `api.go`（暴露给 open_im_sdk 层），服务端 RPC 封装在 `server_api.go`（统一走 `pkg/api` 的 gRPC 调用），数据库访问全部委托 `c.db`，不直接操作 DB；文件上传走 `internal/third/file`。
- 发送流水线：`SendMessage` → `messageSender`（`send_queue.go`，基于 CPU 数并发 worker + 有界 channel）→ `sendMessage/sendMessageNotOss`（按 ContentType 组装内容并触发 OSS 上传）→ `sendMessageToServer` → `sendMsg`（LongConnMgr.SendReqWaitResp）→ 回调更新本地状态并清理临时文件。
- 消息接收与持久化：`doMsgNew` / `doMsgSyncByReinstalled` 解析 `CmdNewMsgComeToConversation`，去重后批量插入/更新消息，diff 出新增/变更会话并写入 DB，再经 `newMessage` 分发到 `OnRecvNewMessage` / `OnRecvOnlineOnlyMessage` / `OnRecvOfflineNewMessage` 回调。
- 历史分页：`getAdvancedHistoryMessageList` 配合 `fetchMessagesWithGapCheck` 做“内部连续性检查 + 块间断点续拉 + 末尾补全”，并用 `ConversationSeqContextCache` 缓存 forward/reverse 两个方向的 endSeq，避免重复拉取。
- 会话增量同步：`initSyncer` 使用 `pkg/syncer.Syncer2` 配置 insert/update/delete/batch/fullSync 钩子，通过 `IncrSyncConversations` 驱动增量拉取。
- 辅助子模块：`revoke.go`、`delete.go`、`notification.go`、`entering.go`、`image.go`、`read_drawing.go`、`progress.go`、`max_seq_recorder.go`、`conversion.go`、`message_check.go`、`incremental_sync.go` 分别承载撤回、删除、通知消息、输入状态、图片处理、阅读进度、最大 seq 记录、协议转换、消息校验、增量拉取等职责，均被 Conversation 方法按需调用。
