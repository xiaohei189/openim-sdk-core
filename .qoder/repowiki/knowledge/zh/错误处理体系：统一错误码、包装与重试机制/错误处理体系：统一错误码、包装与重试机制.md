OpenIM Go SDK 采用基于 `github.com/openimsdk/tools/errs` 的统一错误处理体系，通过 `pkg/sdkerrs` 包集中定义错误码、预定义错误和构造器，配合 HTTP 层统一封装、业务域语义化错误返回以及指数退避重连策略，形成从底层网络到上层回调的完整错误链路。

**1. 错误类型与错误码体系**
- `pkg/sdkerrs/code.go` 定义全局错误码常量（如 `NetworkError=10000`、`ArgsError=10002`、`SdkInternalError=10006`、`MsgRepeatError=10204` 等），按网络、参数、SDK 状态、消息、会话、群组等维度分组。
- `pkg/sdkerrs/predefine.go` 提供预定义的 `errs.CodeError` 实例（如 `ErrArgs`、`ErrNetwork`、`ErrSDKNotInit`、`ErrMsgRepeated` 等），业务代码直接引用，避免重复构造。
- `pkg/sdkerrs/error.go` 暴露 `New(code, msg, detail)` 构造器和 `Wrap`/`WrapMsg` 别名，统一调用 `errs.NewCodeError` + `WithDetail` 创建带详细信息的结构化错误。

**2. 错误传播与包装约定**
- 网络层 `pkg/network/http_client.go` 的 `ApiPost` 是统一入口：JSON 序列化失败、HTTP 请求失败、响应体读取失败均包装为 `sdkerrs.ErrSdkInternal.WrapMsg(...)`；网络异常包装为 `sdkerrs.ErrNetwork.WrapMsg(...)`；服务端返回非零 `ErrCode` 时通过 `sdkerrs.New(baseApi.ErrCode, baseApi.ErrMsg, baseApi.ErrDlt)` 构造并触发 `ccontext.GetApiErrCodeCallback(ctx).OnError(...)` 回调，再向上返回。
- 业务域（如 `internal/conversation_msg/api.go`）直接返回预定义错误（`sdkerrs.ErrArgs`、`sdkerrs.ErrMsgContentTypeNotSupport`、`sdkerrs.ErrMsgRepeated`），或通过 `.WrapMsg("...")` 附加上下文信息后返回。
- 测试与集成代码使用 `errs.New(...).Wrap()` 或 `errs.WrapMsg(err, "...")` 包装原始错误，保持链式可追溯。

**3. panic/recover 策略**
- 核心业务逻辑中极少使用 `panic`，仅在极少数边界场景出现（如 `internal/conversation_msg/progress.go`、`entering.go` 中的 `panic(err)`），且多被 `integration_test/internal/process/process.go` 中的 `recover()` 捕获并转为 `fmt.Errorf("call panic: %+v", r)` 返回，避免进程崩溃。
- 未在生产路径发现统一的 `defer recover()` 中间件，错误主要通过返回值传递。

**4. 重连与容错**
- `internal/interaction/reconnect.go` 实现 `ReconnectStrategy` 接口与 `ExponentialRetry` 指数退避策略（间隔序列 `[1,2,4,8,16]` 秒循环），用于 WebSocket 断线重连时的退避控制。
- HTTP 客户端设置固定超时 `Timeout: time.Second * 10`，超时错误映射为 `NetworkTimeoutError`。

**5. 开发者规范**
- 优先使用 `sdkerrs.ErrXxx` 预定义错误，新增错误先在 `code.go` 添加常量、在 `predefine.go` 注册变量。
- 需要携带额外上下文时使用 `.WrapMsg("detail")`，不要拼接字符串。
- 网络层错误一律通过 `ApiPost` 统一转换，业务层不直接构造 `errors.New`（除测试与极少量校验场景）。
- 对可恢复的网络错误（如 `ErrNetworkTimeOut`）可在调用方判断并触发重连逻辑。
